# The default definition of ready

Use this when the user gives no definition and the project has no `definition-of-ready.md` at its root or in `docs/`.

A work item is ready when anyone on the project can understand its goal and what it delivers, and it meets every criterion below.

## Qualities (INVEST)

| Criterion | Ready when |
|---|---|
| Independent | It doesn't depend on other unfinished work, or the dependency is named and agreed |
| Negotiable | It describes the need and leaves room to discuss the solution |
| Valuable | It says who benefits and how. A user is anyone who uses the software, including another team |
| Estimable | The team could size it from what's written |
| Small | It fits in one iteration |
| Testable | There is a way to tell when it is done |

## Parts

| Criterion | Ready when |
|---|---|
| Description | It says what the item is, what it delivers, and why |
| Acceptance criteria | They are present, specific and measurable, and say what must be true for the item to be accepted |
| Examples | Each has a context, an action and an expected result |
| Open questions | They are listed (or the item says there are none), and none blocks starting the work |
| Verification | It lists the evidence that will show the acceptance criteria are met, such as test results, screenshots or output files |

How to judge each one: [assessing-criteria.md](assessing-criteria.md).
