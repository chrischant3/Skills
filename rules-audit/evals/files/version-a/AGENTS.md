# Project Notes for Agents

Welcome! This is the orders service. It's a TypeScript project that has
grown over a few years, so you'll find a mix of styles. We use Node 20 and
Postgres, and the code lives under src. There's a folder called
src/generated which is produced by our OpenAPI tooling.

## General

We like to keep things tidy. Commit messages should follow Conventional
Commits, e.g. feat: or fix:, and we generally prefer small, focused
changes because they're easier to review. When working with the database,
migrations live in db/migrations and we use the migrate tool. Please don't
put API keys, passwords or tokens in the code; they belong in environment
variables, and the .env file is git-ignored. Migrations are run in CI on
deploy. If you change a migration that's already been merged it will break
other people's databases, so create a new one instead using
npm run migrate:create <name>. Every migration needs a down step too.

## Testing

We care a lot about testing. Integration tests are in tests/integration
and use Testcontainers to spin up a real Postgres, because we've had
bugs slip through when the database was mocked, so please don't mock the
database in integration tests. Mark slow tests with the @slow tag. Unit
tests live next to the code in __tests__ folders. We practise TDD, so
ideally the test comes before the implementation and you should see it
fail first. Before you finish, run npm test and npm run lint.

## Code Style

Use the logger from src/lib/logger rather than console.log. Don't log
email addresses, names or other personal data. Don't edit anything in
src/generated by hand, regenerate it with npm run generate instead.
If you think a new npm package would help, check with a human first
rather than just installing it.

## Frontend

The admin UI is in src/ui. Components should use semantic HTML (button
for buttons, not div), interactive elements need accessible names, and
each component should have an axe test using jest-axe. Labels must be
associated with inputs.

## Reminders

Remember tests should be written before the code where possible. Keep
changes small. Make sure lint and tests pass. Secrets go in env vars.
